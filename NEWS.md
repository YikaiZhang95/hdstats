# hdstats 0.2.0

## Bug fixes

* `nc.hdsvm()` and `nc.hdqr()` ignored the `aval` argument: the SCAD and MCP
  derivatives were always evaluated at their default concavity parameter
  (3.7 and 2). The user-supplied value is now used.
* `nc.hdsvm()` and `nc.hdqr()` failed with an obscure error when `pen` was
  not spelled in lower case (e.g. `pen = "SCAD"`) or was invalid. The
  argument is now matched case-insensitively and validated.
* `nc.hdsvm()`, `nc.hdqr()`, and their `cv.*` versions could not be called
  without a `lambda` sequence. `lambda` now defaults to `NULL`, in which
  case the sequence of the initial lasso fit is used; user-supplied
  sequences are sorted in decreasing order so that `coef()`/`predict()`
  interpolation is correct.
* The C++ kernels modified the user's `pf2` (and `pf`) vector in place when
  it contained negative entries. Copies are now used.
* Supplying a `pf` matrix together with a user `lambda` sequence failed
  unless `nlambda` was also set to `length(lambda)`.
* `cv.hdsvm()` computed the hinge loss on the raw response, which was wrong
  for factor or 0/1 coded `y`; the internal -1/+1 coding is now used.
* Non-convergence is now reported with `warning()` instead of `print()`,
  and the messages no longer refer to Fortran code.

## New features

* `print()` methods for all fitted objects and `plot()` methods for all
  cross-validation objects.
* `hdqr()`, `cv.hdqr()`, `nc.hdqr()`, and `cv.nc.hdqr()` default to
  `tau = 0.5`; `cv.hdhuber()` defaults to `delta = 1`, matching `hdhuber()`.
* Fitted objects record the settings used (`tau`, `delta`, `hval`, `lam2`,
  `pen`, `aval`); nonconvex fits store the penalty `lambda` sequence in
  `lambda` (as well as `nc.lambda`).
* Input validation for `y`, `tau`, `delta`, `hval`, `aval`, and `lla_step`.

## Documentation and infrastructure

* Documentation rewritten to match the code (argument defaults, objective
  functions, return values); package help page and references added.
* Added a `testthat` test suite, a vignette, and a `CITATION` file.
* `NAMESPACE` is now generated by `roxygen2`; `stats` and `graphics` are
  declared in `Imports`.
* Unused internal C++ entry points were removed.

# hdstats 0.1.0

* Initial release.
* Unifies the `hdhuber`, `hdsvm`, and `hdqr` solvers into a single package.
* Coordinate-descent kernels re-implemented in C++ via Rcpp (translated from the
  original Fortran), with the Huber kernel restructured to enable SIMD
  vectorization (~3x faster than the Fortran version).
* User-facing API unchanged from the original packages: `hdhuber()`, `hdsvm()`,
  `hdqr()`, their `cv.*` cross-validation wrappers, `nc.hdsvm()`/`nc.hdqr()`
  non-convex (SCAD/MCP) variants, and `predict()`/`coef()` methods.
* Added `hdrr()`/`cv.hdrr()` for penalized Wilcoxon rank regression.
